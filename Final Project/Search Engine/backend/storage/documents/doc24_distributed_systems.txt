Distributed systems are collections of independent computers that appear to users as a single coherent system. Designing, building, and operating distributed systems requires addressing fundamental challenges that do not arise in single-machine programs: partial failures, network latency, lack of a global clock, and the need to coordinate concurrent processes.

The CAP theorem states that a distributed data store can simultaneously provide at most two of three properties: consistency, availability, and partition tolerance. Consistency means every read receives the most recent write. Availability means every request receives a response. Partition tolerance means the system continues operating despite network partitions. Since network partitions are unavoidable in practice, designers must choose between consistency and availability during a partition.

Replication copies data across multiple nodes to improve availability and read throughput. Leader-based replication designates one node as the primary that accepts all writes and propagates changes to follower replicas. Multi-leader replication allows multiple nodes to accept writes, requiring conflict resolution when concurrent writes modify the same data. Leaderless replication uses quorum reads and writes to tolerate node failures.

Consensus algorithms enable a group of nodes to agree on a single value even when some nodes fail or become unreachable. The Paxos algorithm proceeds in two phases: a prepare phase where a proposer requests promises from a quorum of acceptors, and an accept phase where the proposer sends its value. The Raft algorithm simplifies Paxos by separating leader election, log replication, and safety into distinct subproblems.

Distributed transactions coordinate changes across multiple nodes atomically. Two-phase commit acquires locks on all participating nodes before committing and releases them after. If any participant votes to abort, the coordinator instructs all participants to roll back. This protocol is vulnerable to blocking if the coordinator crashes after participants vote to commit but before sending the final decision.

Message queues decouple producers that generate events from consumers that process them. Producers publish messages to topics without knowledge of which consumers will receive them. Consumers subscribe to topics and process messages at their own pace. Durable queues persist messages to disk so they survive producer and consumer failures. Kafka achieves high throughput by batching writes and using sequential disk access patterns.

Distributed caches store frequently accessed data in memory across a cluster to reduce database load and response latency. Consistent hashing assigns data items to cache nodes based on hash values, minimizing remapping when nodes join or leave. Cache invalidation determines when to remove stale entries and is notoriously difficult to reason about in distributed settings.

Service discovery allows clients to find the network addresses of service instances without hard-coded configuration. DNS-based discovery uses service registry servers that respond to name queries with instance addresses. Client-side load balancing distributes requests across discovered instances using round-robin or least-connections algorithms. Health checks periodically test instance reachability and remove failed instances from the registry.

Distributed tracing tracks request execution across multiple service boundaries to diagnose latency and errors. Trace context propagates unique identifiers through HTTP headers and message metadata. Spans record the start time, end time, and tags for each unit of work within a trace. Trace aggregation systems collect spans from all services and reconstruct complete request timelines for analysis.

Observability encompasses metrics, logs, and traces as the three pillars of understanding distributed system behavior. Metrics provide time-series measurements of system health indicators like request rate, error rate, and latency percentiles. Structured logs capture discrete events with consistent field schemas enabling efficient querying. Alerting rules trigger notifications when metrics cross thresholds, enabling on-call engineers to respond before users are widely impacted.
